How to use PAL

PAL is the PX assistant in Slack. Ask it about client numbers, creative, tasks and how PX does things. It reads the live systems and answers in the thread.

PAL in one minute

PAL works like a colleague who can see every PX system at once. You ask in plain words. It pulls the data, does the maths and replies in the thread, with the source and date range for every number.

Where
The #pal channel, or a direct message to PAL
How
Mention @PAL with your question. It reacts with eyes, then answers in a thread
Follow-ups

Who

Three rules PAL follows
PX campaigns only

Every Meta number covers campaigns with PX in the name, unless you ask for the whole account.

Never invents a number

Each figure comes with its source and date range. If the data is not there, PAL says so.

Drafts stay internal

Client updates are drafts for the team to review and send. PAL never posts one in a client channel.

Start here

Ask anything

You do not need a command. Ask the way you would ask a colleague, and name the client and the time period.

Core job: answer questions that would otherwise mean opening Ads Manager, the CRM, ClickUp and a tracker one after another.
Results and numbers
  • @PAL how did <client> do last week?
  • @PAL what did we spend across all clients this month?
  • @PAL how many booked calls did <client> get from PX ads in October?
  • @PAL how long does a lead take to become a sale for <client>?
Creative
  • @PAL top 3 ads for <client> this month and why
  • @PAL which angles are winning for <client>?
  • @PAL what is <client>'s offer and who is the avatar?
Tasks
  • @PAL where is <task name> at?
  • @PAL what is ready to launch for <client>?
  • @PAL move <task> to client approval (waits for a tick)
Context and method
  • @PAL what did <client> ask for this week?
  • @PAL how does PX structure a cold prospecting campaign?
  • @PAL where is the naming standard written down?
How to get a better answer
Name the client and the dates

"Last week" and "this month" work. So do exact dates. Without a period PAL picks one and tells you which.

One question per message

Several clients or several questions share one 20-minute limit. Split big asks into separate threads.

Say which number you mean

Leads, booked calls and sales come from different places. PAL uses each client's own KPI events, so name the one you want.

Words that mean the same thingSale, purchase, deal won and closed are one thing. So are booking, appointment, call booked and meeting booked. PAL maps each to the right stage in the CRM and the right event in Meta.
Named jobs

Commands

Jobs with a fixed recipe. Type them as written, with the client's name in place of <client>.

Core job: produce the same output the same way every time, so nobody rebuilds a report or an analysis by hand.
Client reports
Monday update

@PAL Monday update for <client>

  • Builds this week's update draft from Meta, the lead tracker and the client's Slack channel
  • Posts the draft in the thread with a short list of things to check
  • 1 to 3 minutes. Run one client per message
End of week update

@PAL EOW for <client>

  • Builds the Monday to Friday draft
  • Fills gaps from the last 7 days of the client's channel
  • 1 to 3 minutes
Report template

@PAL show <client>'s report template

  • Shows the contact, 90-day goal, links, standing instructions and buyer notes the reports are built from
Edit a draft

Reply in the draft's thread: make the wins shorter

  • PAL reposts the revised draft, keeping the format and every number
  • To make a preference permanent, see Teaching PAL
Scheduled runEvery Sunday afternoon (Los Angeles time) PAL builds a draft for every active client and posts them to a private group message, one thread per client. Replying in a thread edits that client's draft.
Analysis
Meta analysis

@PAL meta analysis <client>

  • The full Meta Ads Diagnostic page for one account
  • PAL asks the window first: 1 year (default), 6, 3 or 1 month
  • Posts the top findings and attaches the page
  • 1 to 5 minutes
Funnel analysis

@PAL funnel analysis <client>

  • Walks the 11 funnel stages for the last 28 days against the period before
  • Names the constraint and writes the handover: evidence, likely cause, next action, success metric, review date
  • Add 56d or 90d for a longer window
  • Under a minute
Funnel watch

@PAL canary or @PAL canary <client>

  • The daily check for silent tracking breaks
  • Posts breaks, errors and deploys to #pal every day at noon Los Angeles time
  • Ask for the full list, including watch-level findings
  • About a minute

Sources

What it reads

PAL can only answer from what it can see. Knowing the edges tells you when to trust it and when to check.

Core job: read the live systems, never a stale copy. When a saved note disagrees with live data, PAL trusts the live data and says the note looks out of date.
Meta Ads
  • Any read: insights, campaigns, ad sets, ads, audiences, custom conversions
  • PX campaigns only by default
  • Cannot create, edit, pause or launch anything
The CRM
  • Contacts, pipelines, opportunities and appointments for every PX sub-account
  • Also the client-owned accounts PX has been given access to
  • Read-only. It is the real record of leads, bookings and sales
ClickUp
  • Lists, tasks, fields, descriptions and comments
  • Can propose a comment, status change, assignment, new task or field update
  • Proposals run only after a tick
Google Drive
  • Lead trackers, client profiles, game plans and copy docs
  • Only files shared with PAL's service account
  • If PAL cannot find a doc, it has usually not been shared
Slack
  • Channels PAL has been added to, including client channels
  • Used for context: what the client asked for, what the team agreed
  • If PAL is not in a client's channel, invite it there
PX knowledge
  • The playbooks on this site, and the method files behind them
  • Each client's folder: facts, audits, notes, winners
  • The team's working notes: account IDs, known gotchas, past decisions
What PAL cannot seePrivate direct messages · channels it has not been invited to · Drive files not shared with it · anything in a browser, such as Ads Manager screens or a CRM page builder
Writes

Changes and approvals

PAL reads freely and changes almost nothing. The few things it can change all go through a person.

Core job: PAL proposes, a person approves. Nothing is written until an approver reacts with a tick on the proposal.
How a change happens
1. You ask

"Move this task to ready to launch." PAL reads the task first to check it exists and the change makes sense.

2. PAL proposes

It posts the exact change in the thread and says it is waiting. It never says the change is done.

3. An approver ticks

The change runs when an approver adds a tick reaction to the proposal. No tick, no change.

What PAL can change
  • ClickUp: comment, status, assignee, a new task, a field value
  • A client's report template: contact, goal, standing instructions, buyer notes
  • Its own saved lessons
What PAL cannot change
  • Anything in Meta: budgets, ads, audiences
  • Anything in the CRM
  • Any Google Doc or Sheet
  • Any message outside its own thread
Who can approveTask changes and saved lessons are approved by the systems lead. Report template changes can also be approved by the client success lead. A tick from anyone else does nothing.
Learning

Teaching PAL

PAL does not remember a conversation after the thread ends. Two things do carry forward: saved lessons and report templates.

Core job: turn a correction into a rule PAL follows next time, without anyone editing code.
Saved lessons
  • When PAL gets something wrong, correct it in the thread and say why
  • PAL ends its reply with a proposed lesson
  • An approver's tick saves it
  • Saved lessons load into every future question

Example: that's wrong, sales for this client are counted from the Deal Won stage, not the won status

Report preferences
  • Say "always" or "never" when you give feedback on a draft
  • PAL proposes the change to that client's template
  • A tick saves it, and every future draft for that client follows it

Example: never mention cost per lead in <client>'s update

One-off or permanent"Make the wins shorter" changes this week's draft only. "Always keep the wins to three lines" changes the template. Use the second when you find yourself giving the same feedback twice.
What needs a code change insteadA new data source · a different sheet or ad account for a client · a new command. Send those to the systems lead.
Support

When it is wrong or stuck

What each failure looks like, and what to do about it.

No reaction at all
  • Check you are in #pal or a direct message, and that you mentioned @PAL
  • PAL does not answer in other channels
  • Still nothing after a minute: PAL may be down. Tell the systems lead
"I ran out of time"
  • The question hit the 20-minute limit
  • Narrow it: one client, a shorter period, one number
  • Large CRM pulls across many contacts are the usual cause
"I can't find that doc" or "I'm not in that channel"
  • Share the Drive file or folder with PAL's service account
  • Invite PAL to the client's Slack channel
  • Then ask again
A number looks wrong
  • Check the source and date range PAL quoted
  • Check whether it used PX campaigns only
  • Check which event it counted. Leads, bookings and sales differ by client
  • If it is wrong, correct it in the thread so it becomes a lesson
The answer is too shallow
  • PAL answers on its standard model by default, which is fast and cheap
  • For a hard analysis, add use Opus to your question to get the stronger model
  • Near the monthly budget limit the stronger model is switched off until the 1st
  • Ask @PAL what have you cost this month? to see spend
"PAL is paused"
  • The monthly budget is used up
  • PAL posts a notice in #pal and stops answering until it is topped up or the month rolls over
  • Tell the systems lead if you need it sooner
Always worth doing: when PAL is wrong, say so in the thread instead of fixing it quietly. A corrected thread is how it stops making the same mistake.
Claude Code

PAL Workbench

The same PX systems, run from Claude Code on your own machine. PAL in Slack answers and drafts. The Workbench is where the work that changes things gets done.

Core job: run the PX systems that launch, build and change things, with a person in the seat approving each step.
Where
Claude Code, opened in the PX repository folder
How
Ask in plain words, the same way you ask PAL. Claude reads the repository's rules before it acts
Who
Team members who have been set up with Claude Code and the PX repository
Difference from PAL
It can write: launch ads, build docs and pages, change CRM settings. You confirm before it does
When to use which
Use PAL in Slack when
  • You want a number, a status or an explanation
  • You want a report draft or an analysis page
  • The rest of the team should see the answer
  • You are away from your desk
Use the Workbench when
  • Something has to be launched, built or changed
  • The job has several steps and needs your judgement between them
  • You are working with files: creative, copy docs, pages
  • PAL's 20-minute limit is too short
What you can run
Ad launcher

launch ads

  • Lists the tasks marked ready to launch and what each one still needs
  • Pulls creative and copy, then runs a dry run
  • Builds the campaigns in Meta, always paused. A person turns them on
  • Marks the tasks launched in ClickUp
Client audit

client audit for <client>

  • Runs the Meta analysis first
  • Drafts each tab of the audit doc: overview, buyer psychology, media buying, ad creative, roadmap
  • Builds the audit page once the doc is signed off
Meta and funnel analysis

meta analysis for <client>

  • The same pages PAL produces, with room to dig further
  • Follow-up questions on the same data without a time limit
Client reports

EOW update

  • Monday and end of week updates for several clients at once
  • Drafts go to the person running it, never to a client channel
Creative OS

run the newsletter for <client>

  • The weekly creative newsletter, concepts and briefs
  • Winners by sales, then bookings
  • Static image ad generation
CRM and tracking work

why are ad chats not being tagged for <client>?

  • Reads workflows, calendars, tags and pipelines to find the cause
  • With your go-ahead, makes the fix and checks it against a saved copy
  • Bulk corrections to contacts, tested on a few first
The rules it works under
Nothing goes live by itself

Every Meta launch is created paused. Budgets are not changed without asking. A person turns campaigns on.

Confirm before it writes

Changes to a client's CRM, a shared doc or anything hard to undo are shown first and run only on your word.

Dry run first

Launches and bulk changes run as a test before the real thing, and the result is checked afterwards.

Getting set upYou need Claude Code installed, the PX repository on your machine, and your own access keys in the local secrets folder. Each system has a dry run to prove the setup works before anything real. Ask the systems lead to set you up.
Keep in mindPull the latest version of the repository before you start · never paste a key or password into a chat · two people should not run the launcher on the same tasks at once
