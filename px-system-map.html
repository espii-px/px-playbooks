Funnel strategy

Find the bottleneck, then improve it

The goal

Find the choke point in the funnel by using quantitative data to see where the bottleneck is. Use qualitative data to come up with a hypothesis, and then figure out how to keep improving the funnel. Remember, the funnel is not random marketing activities. It is an acquisition system, and every system is constrained by some sort of bottleneck. All you want to do is find where you can improve it and get better results for the client.

Every funnel is read as the same 11 stages, top to bottom. A stage can only be judged once the stages above it are healthy, so the work always starts at the top.

1Budget→ 2Traffic cost→ 3Traffic fit→ 4Click to page→ 5Page and offer→ 6Form→ 7Tracking→ 8Lead quality→ 9Booking→ 10Show-up→ 11Close
Find the constraint

The numbers say which stage is off. @PAL funnel analysis <client> walks all 11 against the client's targets or its own history, for 28 days and the last 7.

Form a hypothesis

Calls, recordings, lead notes and the page say why. The stage's SOP in playbooks/funnels/ lists what to check, in order.

Change one thing

One test at a time, so we know which change worked. Never rebuild a funnel that works.

Review and repeat

Check the success metric on the review date, then find the next bottleneck. There is always one.

Every diagnosis ends with the same handover. If the evidence isn't there, it says "inconclusive" and what needs to be measured. It never guesses.

1. Observed problemWhich metric is outside its range?
2. EvidenceWhich report, date range and segment?
3. Likely causeWhat does the evidence suggest?
4. Next actionThe single change or test.
5. Success metricThe number that must improve.
6. Review dateWhen the team checks the result.

Changing a report

Edit from Slack, no GitHub needed

Each client's Monday update has a template (its fields plus a notes file in systems/reporting/notes/). You can change it from #PAL.

Ask PAL

Use report template to see a client's template, or report set and report notes to change it.

Approve it

PAL proposes the change in the thread. A ✅ from an account lead approves it.

It's saved

PAL commits the change to the repo, and the next Sunday run uses it. Run one now with report weekly.
